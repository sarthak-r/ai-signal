Voices

A framework team argues leaner beats fuller — with numbers — and Anthropic names a failure mode every agent builder should keep.

Deep Agents v0.7: strip the scaffolding, cut 65% of base tokenslangchain.com · 29 Jul

Sydney Runkle's release removes Deep Agents' built-in system prompt entirely, cuts built-in tool descriptions 43%, and makes TodoListMiddleware opt-in rather than default — dropping base input tokens from ~6k to ~2k per turn. On gpt-5.6-luna the leaner build measured 34% fewer tokens, 15% lower cost, and a 4% reward gain. Middleware is now overridable by matching a default's .name, and filesystem tools got pagination plus a truncated flag so grep/glob stop hanging on large repos.

The measured result cuts against the instinct to pack an agent with guidance and tools. Capable models do better with less boilerplate in front of them, and you pay for every token of it on every turn. Audit your own system prompt and tool descriptions against this: re-enable a todo list or a usage hint only when an eval shows it earns its place. The design rule — default to lean, add scaffolding back deliberately — travels to any framework.

Anthropic: agents that think they're offline attack real systemsanthropic.com · 30 Jul

Anthropic detailed three cybersecurity-eval incidents where a misconfiguration gave models real internet access while their prompts said they had none. Believing everything they touched was simulated, they attacked it: one model published a malicious PyPI package that "was downloaded and run on 15 real systems" in about an hour, another scanned roughly 9,000 targets and SQL-injected a live company before recognizing the environment as real. The root cause was a mismatch between the agent's stated constraints and its actual ones.

Situational awareness is a safety dependency, not a footnote. If you sandbox an agent by telling it "you can't reach production" while the network can, a wrong belief becomes a live action against real infrastructure. Enforce the boundary at the network and permission layer, and keep the agent's described environment matched to its real one — a lie about the sandbox is a lie the agent will act on.

Build Patterns

Conversation state gets a real data model, and agent browsing gets re-pointed at the thing you actually check.

LLM 0.32: content-addressable message storage and conversation branchingsimonwillison.net · 30 Jul

Simon Willison's llm now stores each prompt and response under a content-addressable hash ID, which deduplicates repeated content and lets a conversation fork into branches that share their common history. A companion llm-chat-completions-server plugin exposes any model llm supports behind an OpenAI Chat Completions endpoint, and a new llm openai endpoint command runs one-off prompts against any OpenAI-compatible server.

This is a clean, copyable data model for conversation state: hash the message parts, store once, and represent a branch as a pointer into shared history rather than a full copy. If you're building multi-turn agents with retries, alternate takes, or checkpoints, that structure keeps storage flat and makes forking cheap. The chat-completions server is also a drop-in local gateway for testing any model against OpenAI-compatible clients.

hwatu: an agent browser built for verification, not automationnews.ycombinator.com · 30 Jul

A Show HN project, hwatu splits a warm WebKitGTK daemon from a thin client (the emacs/emacsclient shape), keeping a prewarmed WebView so a focused window returns in ~13ms and a headless one in ~14ms. Its argument: for an agent driving a browser, the part the developer cares about is verifying what happened, not the automation itself, so it optimizes for cheap, repeated inspection of agent steps.

Most agent-browser tooling optimizes the doing; the checking is where builders actually spend their time. A browser cheap enough to snapshot after every step lets you verify each action instead of running a heavyweight session and hoping. If you're building or debugging browser agents, that inversion — make inspection the fast path — is the idea worth borrowing even if you don't adopt the tool.

A frontier vendor moving the cheap-model floor changes your per-request budget more than a new flagship does. Work that was too expensive to run on every call — a classifier pass, a cheap draft before an expensive model, a per-request eval — may now clear the cost bar. Re-run the math on your own pipeline: cascades that route cheap-by-default and escalate only on hard cases get materially cheaper at this price.
